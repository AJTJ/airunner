## 2. Corrections / refinements to `beads-and-gastown.md`

None of §0's headline claims is *false*, but §0.2 and §1.5 are materially incomplete in ways that
affect Air's command surface, so a dated note was added at the top of §0:

1. §0.2 lists what 1.2.2 lacks as leases/heartbeat/reclaim/events/sync/serve/provenance. **Also
   absent from 1.2.2**: `bd unclaim` (entire command), `bd update --if-assignee/--if-status`
   (CAS guards, exit 13), `bd update --force`, the anti-steal refusal on plain `-a`, `--brief`,
   `claim.pools`. (§1.5's `bd unclaim --if-assignee` line and the "refuses to steal / `--force`
   overrides" line are 1.2.1-only.)
2. §1.5 "`bd ready` Excludes in_progress, blocked, deferred, and hooked" understates: it is
   `status = 'open'` only, so custom statuses (adopter's `awaiting_review`, `awaiting_testing`)
   are excluded too (upstream #5831), plus type/pinned/ephemeral/defer_until exclusions (table 4.1).
3. §1.7 should add: TTL is a compile-time 5 m constant (no flag/config), lease rows live in a
   dolt_ignored `leases` table (not issue columns), and heartbeat authorisation is by actor string
   only — any process with the same `--actor` renews.
4. §1.4 "single writer, file-locked": the flock is only held during `bd init`; ordinary commands
   serialize on the Dolt engine lock with driver backoff (30 s open timeout). Same conclusion
   (one writer at a time), different failure mode (waits, then times out; not refused).
5. §1.5 exit-code note: `bd unclaim --if-assignee` mismatch exits 1, not 13 (only `bd update`
   guards use 13).
6. `.claude/skills/beads/SKILL.md` "Known traps (bd 1.2.1)": nothing wrong, but if adopter moves
   to 1.2.2 the entries that mention `bd unclaim` / CAS should be re-checked (not edited here).

## 3. Recommendation for Air

**(a) Version pin.** Move adopter to **bd 1.2.2 and `brew pin beads`**, after running the
cursor rollback (table 5.4) once — adopter's worktrees share one `.beads`, so it is one DB.
Reasons: 1.2.2 is the only *tested* line upstream stands behind ("Do not use" 1.2.1); Homebrew
already wants to install it, so staying on 1.2.1 means every human `brew upgrade` breaks `bd`
until someone finds the recovery doc, while a stray 1.2.1 binary silently re-migrates; the
1.2.1-only features Air would otherwise lean on (leases with a fixed 5 m TTL, node-local, actor
keyed) are exactly what plan 0001 §7 already says to mirror in the ledger; and every command Air
needs exists in 1.2.2 (c). Cost: lose `bd unclaim` and CAS guards — Air's `WorkLedger` becomes
the CAS (release = `bd update <id> -s open -a ""` issued only by the ledger owner after a
generation check). Air should assert `bd --version` == 1.2.2 (or a later *non-retracted* tag)
at startup and refuse 1.2.0/1.2.1 unless `AIR_ALLOW_UNTESTED_BD=1`. Re-evaluate when a release
restores leases/CAS (watch `## [Unreleased]`); none is announced as of today.
Also flip adopter's `events-journal: true` off (1.2.2 does not implement it) and remove the
`node_id`/lease assumptions from its notes.

**(b) Leases.** Do **not** depend on bd leases. Even on main they are: 5 m fixed TTL, per-clone
ephemeral table (survive process restarts but not clones/federation), enforced only where
granted, renewable by any process presenting the same actor string, and reaped only when
something runs `bd reclaim`. Air's ledger keeps `(bead_id, actor, generation, lease_until,
heartbeat_at, worktree)`; on bd the only durable, replicated signal is `status=in_progress` +
`assignee`, and Air should treat those as *mirrors of the ledger*, re-asserted (never inferred)
after crashes. If/when a tested bd release restores `--if-assignee/--if-status`, use them as a
belt-and-braces guard on the mirror writes; keep exit-13 handling behind a capability check.

**(c) Minimal `WorkLedger` command surface — all verified present at tag v1.1.2 (= v1.2.2):**
- read frontier: `bd ready --json [--limit 0] [--parent <epic>] [--label ...] [--exclude-label ...] [--unassigned]` (array; expect only `status=open`);
- read one/many: `bd show <id> --json`, `bd list --json --status in_progress` (`--status` accepts custom names);
- claim: `bd --actor <actor> update <id> --claim --json` (atomic; exit 1 if held by another);
- mirror/release/finish: `bd --actor <actor> update <id> -s <status> [-a <actor>|-a ""] [--append-notes ...] --json` — **unguarded on 1.2.2**, so gate it behind the ledger; never pass `-a` to a bead the ledger does not own;
- evidence: `bd comment <id> "..."`, `bd close <id> --reason ...`;
- graph: `bd dep add <a> <b> [--type blocks]`, `bd blocked --json`, `bd recompute-blocked` after any pull;
- global flags: `--json`, `--actor`, `-C <dir>`, `--readonly` (for reader-only workers), `--sandbox` (no auto-push).
Not needed and not to be relied on: `heartbeat`, `reclaim`, `unclaim`, `events`, `sync`, `serve`,
`--if-*`, `--brief`, `claim.pools`, `set-state`, `merge-slot`, `gate`, `formula`, `mol`.
