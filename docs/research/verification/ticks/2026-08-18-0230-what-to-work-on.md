feature (never automated), what is the best-evidenced, least-machinery process for (a) turning it

concurrent workers and a coordinator traverse an epic (ordering, ready semantics, gates, citation
re-checks, re-cutting siblings, done)? Output: this note and a DRAFT `docs/plans/0002-what-to-work-on.md`.

## 1. What each system does (evidence)

### 1.1 Metis (decomposition + phase-transitions, ADRs)

- Chain Vision → Initiative → Task; decompose **ahead of capacity, not upfront**; explicit
  `decompose` phase as a "visible buffer" (`.claude/skills/decomposition/SKILL.md:38-71`, ported
  from metis `6745810`). Patterns: vertical slices preferred, horizontal "creates dependencies",
  risk-first spike, milestone (`:98-160`). Smells: too granular / too vague / wrong level /
  orphaned / overlapping (`:163-169`).
- Phases forward-only, adjacent-only; only `blocked` returns; pull-based transitions; "the phases
  protect you" (`.claude/skills/phase-transitions/SKILL.md:26-49, 128-137`).
- **ADR-003 Exit Criteria Format** (`~/projects/metis/.metis/adrs/METIS-A-0003.md:29-59`):
  GitHub checkboxes in `## Exit Criteria`, max 7, "All checkboxes must be checked before
  decomposition to child documents", "System validates checkbox completion before allowing creation
  of child documents". **But** the deep dive found `exit_criteria_met()` is a hard-coded `false`
  placeholder and nothing blocks a transition on it; the only code-enforced gates are phase adjacency
  and "tasks may only be assigned to initiatives in `decompose` or `active`"
  (`docs/research/metis-deep-dive.md:110-117`). Human approval of initiative transitions is prose.
- **ADR-007** (`METIS-A-0007.md:25-75`): multi-team/cross-repo out of scope; "zero-infrastructure …
  Better to do one thing well"; the Strategy level "proven to not map to anything real at the repo
  level" and removed. Lesson for Air: fewer levels, repo-scoped.
- Traversal in Metis is single-agent: `/metis-ralph-initiative` lists tasks under an initiative,
  completes each; `decompose` mode creates tasks and a human moves the initiative to `active`;
  nothing verifies before `completed` beyond a promise string (`metis-deep-dive.md:242-256`).

### 1.2 beads primitives (the layer Air keeps)

- **A molecule is just an epic** — "any epic with children is a molecule … Protos and formulas are
  optional layers for reusable patterns … most work needs only epics and dependencies"
  (`~/projects/beads/docs/workflows/molecules.md:6-27`; https://github.com/steveyegge/beads/blob/main/docs/workflows/molecules.md).
- **Execution model**: "An agent picks up a molecule and executes ready children in parallel until
  everything closes … Children are parallel by default. Only explicit dependencies create sequence."
  Loop: `bd ready --mol <id>` → `bd update --claim` → work → `bd close` → repeat (`molecules.md:79-99`).
- Blocking edge types: `blocks`, `parent-child` (blocked parent blocks children), `conditional-blocks`
  (B only if A fails), `waits-for` (B waits for A's dynamic children); non-blocking `related`,
  `discovered-from` (`molecules.md:101-113`; `docs/research/beads-and-gastown.md:45-49`).
- **Ready = the claimable frontier**: "open beads with no open blockers, excluding anything in
  progress, blocked, deferred, or held by a gate"; `bd ready` excludes `in_progress/blocked/deferred/
  hooked`; filters `--parent/--mol/--label/--exclude-label/--sort priority|hybrid|oldest/--explain`;
  `--claim` atomically claims the first match; `--gated` finds molecules whose gate just closed
  (`beads-and-gastown.md:67-73`; `bd ready --help`, bd 1.2.1 local).
- **Done for an epic**: "Closing the last child does not close the molecule root — epics stay open
  as close-eligible work until closed explicitly (`bd epic close-eligible` sweeps them)"
  (`molecules.md:178-180`); `bd epic status` shows completion (`bd epic --help`, local).
- **Gates**: issue type `gate`, `await_type ∈ {human, timer, gh:run, gh:pr, bead}`; "blocks a step
  the same way any blocker does"; `human` closes only by `bd gate resolve`; `timer/gh:*` by
  `bd gate check` on a schedule; "Waiting on other steps is not a gate — it's a dependency"
  (`~/projects/beads/docs/workflows/gates.md:1-40, 149-170`; https://github.com/steveyegge/beads/blob/main/docs/workflows/gates.md).
- **Formulas**: TOML `[[steps]] id/title/needs/type`, `[steps.gate]`, `[vars]`, aspects, `bd cook`
  → proto → `bd mol pour`; "Step-completion hooks are not currently exposed as runnable formula
  actions" (`docs/workflows/formulas.md`; `molecules.md` "Hooks"). Agent pitfalls the doc itself
  lists: temporal language inverts edges; numbered steps don't create sequence; forgetting to close
  (`molecules.md:258-268`).
- Field-tested traps that shape any process here: `--design=-` stores a literal `-`; `--notes`
  overwrites; `bd ready --label '!owner'` silently matches nothing; `validation.on-create: warn`
  creates anyway, `bd create --validate` refuses (`.claude/skills/beads/SKILL.md:191-250`).

### 1.3 Gas Town (formulas → protos → molecules; convoys; refinery; integration branches)

- MEOW stack: beads → epics → molecules → protomolecules → formulas; wisps for patrol noise; root-only
  wisps "steps materialized at runtime" to stop "~6,000+ rows/day" accumulation
  (`beads-and-gastown.md:134`; https://github.com/gastownhall/gastown/blob/main/docs/concepts/molecules.md, accessed 2026-08-18).
- **Convoy** = "persistent tracking unit … `tracks` relation is non-blocking, additive, cross-rig";
  "It doesn't use the Epic structure, because the tracked issues in a Convoy are not its children";
  lifecycle `OPEN ──(all issues close)──► LANDED`; `gt convoy create --from-epic` BFS-walks an epic
  and tracks only leaf work items; "Stranded convoy: ready work but no polecats assigned"
  (https://github.com/gastownhall/gastown/blob/main/docs/concepts/convoy.md, lines 21-77, 181-251,
  accessed 2026-08-18; `beads-and-gastown.md:133`).
- **Integration branches**: per-epic shared branch; polecats spawn from it "so they start with
  sibling work already present"; refinery merges MRs into it; "Sling the next wave. When a wave
  completes and its dependent children unblock, sling the next batch"; "When all children under the
  epic are closed, the integration branch is ready to land … as a single merge commit, deletes the
  branch, and closes the epic"; the motivating problem is "epic work lands piecemeal … relying on
  merge order" (https://github.com/gastownhall/gastown/blob/main/docs/concepts/integration-branches.md,
  lines 1-100, accessed 2026-08-18).
- Refinery: batch + bisect + gates; polecat completion self-managed; "Witness observes but does NOT
  gate completion" (`beads-and-gastown.md:148`). Cost/criticism: ~$100/h, "merged a pull request
  despite failing integration tests", "collapses on novel design work" (`beads-and-gastown.md:154-158`).

### 1.5 adopter 0022 and the task-specification note

- **Commitment point**: "`bd create` writes directly into `bd ready`, so every observation … is
  instantly committed work" — the defect; capture (one line: what, `file:line`, which bead) is free;
  triage is "a separate pass with the whole inbox in view" that (1) links to an existing bead's
  *acceptance*, (2) buckets, (3) writes the acceptance line, (4) labels `owner/human`, (5) records
  edges where files overlap, (6) creates — or drops with a reason
  (`docs/research/adopter-notes/plans/0022-agent-working-procedure.md:58-64, 105-143`). Evidence it
  cannot be done on the hot path: dedup only ~3%, but a scope collision and three missing edges
  "nobody had seen" (`:85-103`). Metis "contributes nothing" here (`:78-82`). Failure to watch:
  triage becoming a bottleneck ⇒ auto-file trivial captures with `triage-needed` (`:276-280`).
- **Task spec**: acceptance = "one observable condition, checkable inside a worktree by the agent
  that must satisfy it"; title = defect/outcome never the fix; how it fails; the trap; tried/failed;
  the boundary; `--design` for anything architectural; stop rule: description vs acceptance
  contradiction ⇒ `bd human` (`docs/research/adopter-notes/notes/task-specification-research.md:622-671`).
  What survived verification: "Acceptance criteria are the weak link, not descriptions … Executable,
  red/green-probed acceptance criteria are the right response"; "Guidance is navigation";
  "Contradictions are silent … only an executable probe surfaces" (`docs/research/verification/specs-guards-tooling.md`
  "Claims strengthened"); SDD is assertion, Radar ASSESS, "agents frequently ignore detailed
  specifications" (`task-specification-research.md:307-340`).
- The queue defect adopter measured is direction, not writing: "the ship path was invisible for a
  month … 113 of 304 closed beads are pure agent infrastructure … what the queue was configured to
  produce" (`docs/research/adopter-as-built.md:202`).

### 1.6 Spec-driven / plan-then-execute guidance (external, primary)

- **spec-kit** (GitHub): `/speckit.specify` ("what and why, not the tech stack") → `/clarify` →

  (https://github.com/github/spec-kit/blob/main/README.md, accessed 2026-08-18). `tasks-template.md`:
  format `[ID] [P?] [Story] Description`, "**[P]**: Can run in parallel (different files, no
  dependencies)", "Include exact file paths", tasks grouped by user story so each can be

  "Foundational (Phase 2) … BLOCKS all user stories" then "User stories can then proceed in parallel
  (if staffed) or sequentially in priority order"; per-story "Independent Test" and "Checkpoint"

- **Anthropic, *Best practices for Claude Code*** (https://code.claude.com/docs/en/best-practices,

  success"; "Explore first, then plan, then code … If you could describe the diff in one sentence,
  skip the plan"; "The most useful specs are self-contained: they name the files and interfaces

- **OpenAI Codex, *Best practices*** (https://learn.chatgpt.com/guides/best-practices, redirected

  the task is complex, ambiguous, or hard to describe well, ask Codex to plan before it starts
  coding"; "run the relevant checks, confirm the result, and review the work before you accept it";
  "A short, accurate AGENTS.md is more useful than a long file full of vague rules".

Convergences worth stating: (i) every multi-agent system pulls leaves from a **ready frontier**
computed from edges (beads, Gas Town, Symphony); none traverses an epic in a coordinator's head.
(ii) The only systems with a **commitment line** are Symphony (Backlog→Todo by a human) and
adopter 0022 (capture→triage); Metis and Gas Town lack it and Metis's ADR-003 gate is unenforced.
(iii) Every guidance source makes the **check**, not the prose, the done signal (Anthropic Stop
hook ladder; Codex "run the relevant checks"; spec-kit "Independent Test"; task-spec note; Symphony
"Validation … non-negotiable"). (iv) "Foundational first, then stories in parallel" recurs
(spec-kit Phase 2, Gas Town waves, Metis risk-first) and is expressible with `blocks` edges alone.
(v) Everything beyond epic + edges + ready is optional in its own docs (beads: "most work needs only
epics and dependencies"; Metis ADR-007 removed a level; convoys exist for cross-rig, which Air is not).

## 3. Minimum viable process for Air (recommendation)

**Layer 0 — feature (owner; no machine state).** One paragraph in `docs/decisions.md` or a plan;
Air stores nothing (`.claude/skills/phase-transitions/SKILL.md:19`).

**Layer 1 — feature → epics (coordinator or a dispatched decompose session; skill, not code).**
- Only when the ready frontier is thin — decompose ahead of capacity, never the whole feature
  (Metis, `decomposition/SKILL.md:38-49`; spec-kit MVP increments).
- One epic = one capability increment, vertical slice preferred; the epic's `--design` (non-empty
  — check 8) is the self-contained spec Anthropic describes: files/interfaces, out of scope, risks,
  and **the epic's own end-to-end verification step** (a command). Use `--design-file -`
  (`beads/SKILL.md:201-204`).
- Skip the plan when the diff fits one sentence (Anthropic) — then it is a bead, not an epic.

**Layer 2 — epic → beads: the triage commitment point (this is the one thing to *enforce*).**
A child is offered by `air next` / counts as `triaged` only when all hold (SYNTHESIS §4.3 check 4;
0022 §4 steps 3-6; task-spec §3):
1. `--acceptance` is one observable condition runnable inside the worktree — write the check
   (command or test name), not prose; contradiction with the description ⇒ not filed, `bd human`.
2. lane label (which files/dirs it will touch — the partition; corpus §0.4) and `owner/human/runtime`
   applied at filing.
3. edges recorded: `blocks` for ordering and for any file shared with an open sibling;
   `parent-child` via `--parent`; `bd dep cycles` empty.
4. citations (`file:line`) resolve at filing.
Until then a capture is an option, not work (Kanban commitment line, 0022 §2). Mechanism: `bd create
--validate` for the acceptance field today; Air's `next` filter for the rest; a `triage-needed`
label auto-file only if captures pile up (0022 §8).

**Layer 3 — traversal (few workers + coordinator).**
- Ready = `bd ready --parent <epic>` (children parallel by default; only edges sequence). Order =
  priority, then oldest (Symphony §8.2; `bd ready --sort`); the coordinator sets priorities and
  can pin "foundational first" purely with `blocks` edges (spec-kit Phase 2 / Gas Town waves).
- Concurrency = a few workers (≤4, corpus §0.6), WIP ≤2 per worker (check 9), one live claim per
  lane (check 6). Symphony's per-state cap maps to one Air number worth measuring first: how many
  beads may sit in `awaiting_review` before the coordinator lands (the human is the constraint,
  corpus §0.5) — measure before capping.
- Claim: `air claim` verifies citations (check 5) and declares the lane; a stale citation closes the
  bead with the finding instead of doing the work (`beads/SKILL.md:243-246`).
- **Re-verify citations** at claim, and again after any merge that touched cited files
  (`air post-merge`, plan 0001 §3); when a sibling lands, `air next` re-checks the remaining
  siblings' citations and prints "stale since <sha>" — that is the signal to re-cut.
- **When a task's result re-cuts siblings**: (a) a spike closes (risk-first) — decompose the rest
  now, not before; (b) a landed sibling changed files a sibling cites or made its acceptance
  already true ("if it is done, close it; finding that out is the work", `beads/SKILL.md:247-251`);
  (c) description/acceptance contradiction discovered — `bd human`. Re-cutting is coordinator
  judgement (close with reason + `supersedes` edge, file successors); Air only flags.
- **Gates**: the only gate Air adds is the hand-over refusal (green at HEAD + main merged, plan
  0001 §4). Human decisions stay `bd human` / `owner` labels (which already withhold from
  `make ready`); no gate beads until a named pain (bd's `human` gate is the same shape if ever
  needed; `timer`/`gh:*` have no local meaning here).
- No hook blocks on a question; a run must not stall on input (Symphony §10.5; corpus "deadlines
  ask, don't kill").

**Layer 4 — done.** Child: `bd close --reason` with landed sha + acceptance evidence, only after
`land` (phase-transitions skill). Epic: all children closed or superseded **and** the epic's own
end-to-end check recorded green on `main`; then `bd close <epic>` naming shas (or `bd epic
close-eligible` as the sweep, with the check as the extra condition). Progress view: `bd epic status`
+ `air status`; no convoy.

## 4. What NOT to build (anti-cruft; `docs/decisions.md:40-41`)

- **Formulas / protos / molecules / wisps engine.** "A molecule is just an epic"; formulas exist for
  *repeated* shapes and step-hooks are not even wired (`molecules.md`); Air has no repeated epic
  shape yet. Revisit only when the same epic template is poured a third time.
- **Convoys.** Cross-rig tracking; Air is one rig; `bd epic status` + `air status` cover progress.
- **Integration branches / refinery per epic.** adopter lands piecemeal to `main` with `make land`
  and round 2 had zero conflicts (SYNTHESIS §1); coherence between siblings is a `blocks` edge.
  Add only after a measured "landed A broke B" incident.
- **A code-enforced epic phase machine.** 0022 §6 ("code fails confidently"), Metis's own
  exit-criteria gate is a stub. Enforce only two evidence checks: non-empty `--design` before a
  child claim (8) and the triage commitment (4). Epic phases stay a skill/label vocabulary.
- **spec/plan/tasks markdown triple (spec-kit / Kiro).** Böckeler: this repo is spec-first already;
  Radar ASSESS; agents ignore long specs. The epic `--design` + acceptance lines are the spec.
- **An LLM decompose/triage daemon.** Triage is a dispatched session on a cadence, holding no lane
  (0022 §4); Air only measures capture depth and time-to-triage.
- **Automated feature selection or priority inference.** Owner's, by decision.
- **Timer / gh gates, per-state caps for every state, task checklists, `waits-for` fan-in beads.**
  No named pain; parent + close-eligible does fan-in.
- **Auto re-cutting of siblings.** Air flags stale citations/acceptance-already-met; a person cuts.
